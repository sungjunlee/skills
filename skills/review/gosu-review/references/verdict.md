# gosu-review verdict boundaries

The panel brief in `SKILL.md` carries the three-line definition; this file is the worked boundary for choosing between neighbors. Panels collapse to `fix` when verdicts have no definition — pick by where the artifact stands, not by whether you found something to say.

- **ship** — it would land as-is; remaining findings are optional. Zero findings earns ship, and so do findings you would not block on. Ship is a complete answer, not a missed opportunity.
- **fix** — specific named changes, then it lands. You can point at each change (file, section, mechanism) and say the artifact lands after it. If you cannot name the changes, it is not fix.
- **rethink** — the approach is wrong, not the details. Listed fixes would not save it: apply them all and the core problem remains, because the premise, mechanism, or direction is the problem.

## Choosing between neighbors

- **ship vs fix**: would you block this on the findings? Optional polish, taste notes, and future ideas do not block; a named defect that hurts a real user does.
- **fix vs rethink**: apply the proposed fixes in your head. If the artifact then stands, it is fix. If the same failure survives the fixes, the approach is wrong — rethink, and say what a right approach would look like rather than re-listing fixes.
- When findings are few and mild, resist defaulting to fix because fix feels productive. A panel that always says fix says nothing: the verdict must carry which of the three the evidence supports.
